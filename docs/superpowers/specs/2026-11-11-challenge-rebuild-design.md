# 挑戰模式重規劃設計

基準：私人網站第 64 版，c8d83fda73ca9de58fc163f64124a3579db5f0d5。這份設計只供隔離候選實作與驗收；不授權發布。

## 目的與邊界

讓四章使用一套可靠的視窗、觸控、鏡頭、角色整備和存檔流程。保留開場漫畫、各章故事、街景、小怪、Boss、21 招、既有動作素材與原畫質。沿用遊戲的諷刺漫畫、墨綠粗框、奶油紙、標誌與實體按鍵感，不把未確認的概念預覽當作規格。

不新增第五章、3v4、分支解鎖技能、付費、網站遷移或分享權限。普通怪於新嘗試可再領 XP，首通獎每槽只領一次。每角享有同額獨立配點額度，不共用扣點池。

## 採用方式與取捨

保留可玩的內容及已測過的戰鬥／章節轉移核心，在邊界加入共用視窗控制、角色能力、全新存檔與單一整備介面。這比重寫全部遊戲更容易證明內容沒有遺失。拒絕固定 Y 偏移補丁、靠降畫質處理卡頓，或保留看似可按實際停用的第二套技能頁。

舊測試存檔不必遷移。新版本使用獨立存檔命名空間與一個全章資料權威，舊鍵不寫、不刪、不自動拿來補進度。舊資料可匯出保留，但不宣稱新版本能匯入所有歷史格式。

## 一套流程

1. 挑戰總覽：目前槽、章節／檢查點、主角助拳、繼續或開始、出戰準備、已解鎖重訪、存檔管理。明示接續的是路段檢查點，不承諾逐幀還原戰鬥位置。
2. 出戰準備：出戰主角、助拳、難度、角色能力／配點與招式。檢視角色不換主角，角色按鈕明確區分「設為主角」「設為助拳」。先改草稿，再取消或確認。從總覽進來只保存配置，不偷偷開始戰鬥。
3. 戰前與完成路段的交界可整備。正常接續沿用氣勢、助拳、揪團；小／大 Boss 入場重置滿氣勢、助拳可用、揪團歸零。大 Boss 每小局沿用原重置規則。
4. 暫停主操作：繼續、重試本段、設定、返回挑戰總覽；次要「查看角色」唯讀且關閉後仍暫停。重試可選沿用配置或重新整備，確認時明示街道重開本段、小頭目重開本場、大頭目整場三戰兩勝且比分歸零。
5. 戰鬥中不提供隱性即時配點或換角。結果依失敗、街道完成、小頭目完成、大頭目小局、章節完成分別顯示操作。第四章完成仍明示第五章未開放並安全回總覽。
6. 返回總覽先完成或處理待保存事件；失敗不得悄悄離場。離開未完成路段的提示說明將從本路段檢查點重新開始，已保存 XP 保留。

### 資源與整備的細節決定

安全交界改主角或增加氣勢上限不免費補血：保留氣勢數值並夾到新上限，保留揪團；換助手保留助拳使用／充能狀態，依新主角上限換算已受傷充能量，不能免費刷新。小／大 Boss 入場才按既有規則重置。明確重試則按該戰重新開始的規則重置，使用者可重試練等。這是避免整備繞過「沿路保留」的技術決定。

### 能力雷達與技能樹

保留類似原技能樹的七支卡與連線語彙，清楚寫無前置限制、不解鎖新招。編輯模式每卡有投入／5、每點效果、下一點變化與 ＋／−；唯讀模式不顯示假的可按 ＋。

雷達用同一實際能力計算：淡線為天生、實線為已保存能力、編輯時虛線為草稿。七軸是氣勢、走速、普攻、耐傷、絕招傷害倍率、揪團傷害倍率、助拳傷害倍率；耐傷指數 = 100／承傷倍率。其餘依共同基準換為 100 指數。所有角色固定 0–140 刻度，不個別放大、不合計為戰力。圖旁列真實值與「基本 → 加點 → 結果」。後三項相同不代表各角色招式一樣強。招式卡列真實基礎傷害／加點後傷害、冷卻及特殊效果，傷害說明未計對手防守。

## 全新三槽保存與單槽重置

新命名空間 taiwanpunchline-challenge-v4；每槽含獨立 generation，外層 revision 單調增加。只使用目前 campaign 核心，不引入舊 v1/v2/v3 權威選擇或自動遷移。

初始槽為王／韓、一般難度、第一章開場未讀、XP 0、零配點、初始解鎖。重置「重新開始本槽」必須顯示槽號、清除項目與兩個其他槽／設定不變；可先下載該槽備份，並在寫入前建立可讀回的復原備份。先保存和精確讀回新世代，再離開舊場景。取消不寫；失敗保留原場景與可重試復原，不假成功。

重置後舊分頁的草稿、戰鬥事件、延遲保存、舊匯入不得把舊進度寫回。單槽備份還原也只作用明確選定的一槽，匯入前摘要並確認，其他槽保留。全份匯出可供復原，但不把單槽匯入說成三槽替換。未知／毀損格式停止寫入並允許匯出原始內容。

所有變更用 Web Locks 協調，revision + generation + 原始字串比較；保存結果需 accepted 與 persisted 都成功。缺鎖時不可假裝正式保存。狀態為保存中／已保存／需處理；未初始化的新檔不誤標保存錯誤。正式玩家資料只在實際玩家自行使用新版時依明確操作改寫，開發驗收使用隔離合成存檔。

## 視窗、輸入與效能

共用 controller 管理 physical viewport、safe content、logical game、已提交 geometry epoch。縮放合法偏移仍保留；scale 1 的 viewport 需在可用範圍內，不能將完整高度再加 offset 超出頁面。旋轉／工具列轉場先清 hold/capture、暫停輸入，shell、app、canvas、dialog 一起提交；根據經過時間、連續幾何與實際 rect 穩定後才 ready，不在固定第 12 幀強制 ready。晚到 safe-area 有界複查；逾時留可解釋的保護狀態，事件再恢復。各章、bootstrap、回前景/pageshow 共用規則，不做 95px 或 109px 固定補丁。

搖桿與按鍵使用相同 committed epoch，按鍵仍用原生 hit-testing；旋轉前後手指不殘留。安全區只扣一次，維持人物和完整控制在可用區。桌面正常構圖須保護。

街道鏡頭使用既有出怪資料提早構圖，不改出怪、AI、碰撞或角色大小。主體納入／移除具遲滯及停留；先平移後縮放。dynamic 平滑跟交戰群；stable 保留交戰尺度與 dead zone。正常出怪目標單幀 zoom 變化 ≤2%，>5% 列失敗；旋轉／切場另列，不准為平順裁切玩家或當前近身威脅。

背景快取 key 只含內容版本、viewport/DPR 密度與固定場景幾何。coverage 只擴不縮、越界才擴一次、切場回收且有界。保留原素材、DPR、裁切、世界錨點與層次。後章使用等價靜態快取、HUD 僅變值更新、幾何 dirty 時才測量、同尺寸不重設 canvas。除非另有證據，不改戰鬥時間步進政策。

## 驗收與限制

先建立第 64 版全 tracked-source 備份、重新下載還原、逐檔校驗及新跑基準，再修改隔離副本。來源、素材、故事與招式有前後 manifest。

測試包含四章街道／小大 Boss、兩相機、直向／原生橫向／左右側轉／桌面；320×568、390×844、430×932、844×390、568×320 加桌面與模擬 safe inset。實際瀏覽器核對真保存、關閉再開、頁面重載、持續／重複輸入、故障復原、單槽重置及兩個獨立分頁衝突。測量同種輸入的鏡頭幀差、快取刷新數與像素品質；效能分位數只在實際完成量測時才報。

七角驗證低氣勢、模式隔離、雙方對稱、超時比例、21 招回歸；以多策略與左右交換的對戰及挑戰路段檢查明顯異常。自動對戰結果不等於真人平衡。不具實機時，明確列 iPhone Safari／PWA、Android、多指與工具列 compositor 未驗。

最終完整測試、建置、獨立審查和候選來源備份重新下載還原後才交付。仍不發布，等待另行許可。

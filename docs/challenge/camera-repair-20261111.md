# 共用鏡頭修正與量測範圍（2026-11-11）

本次修正使用 #65 `29f347d8305c87d15d04033c8c6e0a0a2fdc8a52` 作為基準。這是原始模組的確定性幀追蹤和桌面 Chromium 的實際 DOM 幾何測試，不是手機實機、FPS 或記憶體實測。

## 共用改動

- `challenge-camera.mjs`：安全求解器不能在按鍵周圍彼此分離的可用區域間直接跳接；在可連續到達的位置求解。街道按實際怪物攻擊距離建立本地交戰群，保留投手威脅、玩家和助拳；遠處近戰怪正常走入畫面。縮放從較遠構圖恢復，不永久保留最遠預告尺度。對戰仍包含雙方。
- `preview/campaign/mobile-camera-adapter.mjs`：後章採用同一鏡頭輸出的最高背景繪製密度。
- `preview/campaign/street-static-cache.mjs`：向上取整到 1/64 原圖像素密度，避免跨過 1 倍需求便配置 2 倍密度；始終滿足 DPR × 最大縮放。保留既有只擴不縮、16 Mi 像素與 8192 邊長限制。

角色素材、DPR、傷害、碰撞、AI、世界出怪與存檔規則沒有由這些改動修改。

最終相機、快取與 landmark 合併回歸共 201 項通過；其中新增相機行為／實測幾何 45 項、密度 3 項。完整專案整合測試由發布流程另外執行。

## 動作與幾何驗證

幾何涵蓋 1280×720 桌面、390×844 直向、844×390 原生橫向和側轉的 VS／街道，以及 1366×768、1440×900、1920×1080 桌面 VS。使用頁面實際 safeRect／遮擋矩形。最終直向街道提示為 y140–160，hudBottom160。

- 原生橫向／側轉穩定 VS：兩方向連續走跳的單幀平移，主入口由 47.6–89.2 px 降至 2.8–3.1 px；後章接頭結果相近。
- 桌面真 Duel：玩家地面操作、AI、碰牆、跳躍和反向移動可重現原本約 41–153 px 的側向跳接。候選所有測試的最大水平移動 ≤2.83 px；雙方皆落地的總移動 ≤2.85 px。純地面來回本身沒有重現同樣的大跳接，因此仍需使用者確認原本看到的具體時刻。
- 跳躍不能以「任何方向每幀都不得超過 3 px」判斷。最大的剩餘 17–25 px 是垂直追隨下降角色：相機與玩家同幀都下降 14.2778 世界單位、縮放不變；不是無對應人物動作的側向切鏡。
- 主入口和後章街道均測原引擎出怪、實際按拳、擊倒、助拳、三路段、後三章、跳躍與兩模式。原生橫向動態街道仍有約 3.3% 的單幀安全縮放，其餘本次量測街道 ≤2%；不宣稱所有情況恆定 2%。

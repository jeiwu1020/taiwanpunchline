## 修正範圍

- 四章及一般 VS 繼續使用同一個相機安全求解器。鏡頭以連續可達的位置取代跨越控制區的瞬間換位；街道聚焦玩家與附近交戰者，保留真正有攻擊距離的遠攻威脅，不改敵人、出怪、AI 或碰撞。
- 街道人物拉近後，背景快取按共用最高構圖密度預留，保留原素材與解析度，避免每次拉近重新配置。
- 總覽、出戰準備及存檔管理使用同一頁框。配點仍是草稿，取消或切頁不寫入，確認才使用既有保存交易。
- 出戰準備的確認列獨立於捲動內容，不透明且不露底。戰前、重試與唯讀檢視共用同一能力元件，不新增另一套保存邏輯。
- 手機直向頂列依序為標題、保存狀態、四個工具按鈕；街道提示移到整個 HUD 下方。暫停的查看能力按鈕沿用其餘按鈕形狀，使用不同配色。
- 桌機漫畫在一頁內顯示，四個導覽按鈕風格一致。短手機長文保留必要的垂直閱讀捲動，不以過度縮小文字消除捲軸。
- 開始挑戰保留來源介面直到已保存的目標場景實際完成繪製，不再以固定幀數或等待時間遮掩舊議場畫面。保存失敗與已保存但場景無法開啟分開處理。

## 驗證限制

- 沒有實體 iPhone、Android、Safari、PWA 或應用程式內 WebView 驗收。桌面滑鼠、wheel 和合成觸控回歸不能代替實體多點觸控。
- 相機在跳躍、受擊和真正遠攻交戰時仍須保持完整人物可見，不能承諾永遠固定近景或完全不移動。移動是否仍感到跳接需要區分事件和方向。
- 來源備份不包含玩家瀏覽器中的存檔。更新候選不得清除 v4 資料；回退時也不得清除瀏覽器資料。
- 一般新入場、延遲保存、保存失敗復原、Boss 漫畫至倒數的瀏覽器觀測沒有露出舊議場。場景 shutdown 與 Canvas 故障另用真實保存控制器、模擬渲染生命週期測試，不是實際手機故障證據。
- 第 2／4 章返回總覽的瀏覽器檢查止於確認視窗；第 3 章確認了實際返回網址。瀏覽器沒有逐章跑完所有頭目戰與所有故事分鏡；其他路徑由既有及新增回歸測試覆蓋。
